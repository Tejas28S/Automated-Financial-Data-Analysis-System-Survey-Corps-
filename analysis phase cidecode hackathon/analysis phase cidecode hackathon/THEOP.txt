SECTION 1 — OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The Analysis Phase is an automated, end-to-end financial fraud detection pipeline
implemented in Python. It has been successfully upgraded from the initial 10-pattern
baseline to a comprehensive 21-pattern detection engine. It ingests normalized bank
transaction data, loads it into an optimized relational structure, computes custom
statistical baselines, builds multi-dimensional graph networks, applies deterministic
heuristics to catch suspicious behaviors, and constructs ranked risk reports.

The system is designed to:
  • Ensure zero hardcoding: All detection thresholds are derived dynamically from the
    dataset's statistical distribution (e.g., quantiles, medians, and scale-relative limits).
  • Achieve high cohesion and low coupling: Each pattern is implemented in its own
    module with a single responsibility, depending only on shared models and helper modules.
  • Construct unified graph structures using NetworkX to track money flows (round trips,
    transit nodes, multi-hop circular loops, and centrality-based hub rankings).
  • Package results into a structured, immediate-action report (report.json & report.txt)
    for financial crime investigators.

SECTION 3 — PIPELINE ORCHESTRATION STEPS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Every execution of the AnalysisPipeline runs through the following sequence:

Step 1 — INGESTION & NORMALIZATION
  Ingests CSV files, normalizes columns (txn_id, account_id, amounts, narrations),
  interprets date formats, and computes initial row statistics.

Step 2 — SQL DATABASE HYDRATION
  Hydrates the internal SQLite transaction tables. Sets up optimization indexes on
  accounts, dates, references, and transaction IDs.

Step 3 — BASELINE COMPUTATION
  Estimates quantiles (P50, P75, P90, P95, P99) of positive transaction amounts,
  calculates typical gaps in active dates, and establishes the initial parameters.

Step 4 — BALANCE CHAIN CONSISTENCY VALIDATION (Pattern 3 Gate)
  Sequences transactions chronologically per account. Validates that balance changes
  match (Credit - Debit). Flags mismatch anomalies as extraction errors, excludes
  them from subsequent processing, and logs Pattern 3 findings.

Step 5 — BASELINE ADJUSTMENT & COUNTERPARTY RESOLUTION
  Re-estimates baseline metrics if balance gating changed row eligibility. Resolves
  payment counterparties via reference codes, ledger matching, and cached LLM fallbacks.

Step 6 — SUSPICIOUS BEHAVIOR DETECTION (Patterns 1–21)
  Executes detectors in logical groups:
    • Single-Account Detectors: Duplicates (P1), Reversals (P2), Structuring (P7),
      Credit-to-Cash (P14), Round-Value Debits (P16), Reversal Clusters (P18).
    • Graph Building: Money Flow Graph Construction (P8) is run to assemble the NetworkX multigraph.
    • Graph Detectors: Round Trips (P4), Transit (P5), Accumulation (P6),
      Circular Cycles (P9), High Throughput (P11), Account Testing (P19), Hub Ranking (P20).
    • Cross-Account Detectors: Internal Flows (P12), Cross-Statement Links (P13),
      Holding Profiles (P15), Shared UPIs (P17).
    • Special Detectors: Traces Money Trails (P10) from credit hooks if explicitly requested.
    • Meta-Pattern: Top Suspicious Rankings (P21) aggregates all findings and generates a
      comprehensive risk profile.

Step 7 — ACCOUNT SUSPICION SCORING
  Combines all triggers. Accounts are scored primarily based on pattern trigger breadth
  (number of distinct patterns triggered) and secondarily on total finding counts.

Step 8 — OUTPUT GENERATION & REPORT SERIALIZATION
  Saves the SQLite database and writes out structured report files (report.json and report.txt).

SECTION 4 — THE 21 CANONICAL FRAUD PATTERNS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Pattern 1 — Duplicate Transaction Cross-Check
  Identifies identical/cloned records occurring within close date windows (1 day),
  having near-identical amounts (±0.5%) and high narration similarity (≥80%).

Pattern 2 — Failed / Reversed Transaction Detection
  Matches debits and credits on the same account that mirror each other within a
  typical transaction gap window and feature reversal keyword matches.

Pattern 3 — Balance Consistency Validation
  Verifies that chronological transaction chains perfectly reconcile against printed
  balances. Serves as a data-integrity checkpoint.

Pattern 4 — Round Trip Detection
  Traces directed paths (A → B → ... → A) where funds return to the sender account
  within a set settlement window with high value retention.

Pattern 5 — Transit / Pass-Through Detection
  Flags accounts with near-zero net balance retention (debit ≈ credit), high volume,
  and a broad footprint of unique counterparties.

Pattern 6 — Accumulation Account Detection
  Identifies accounts acting as sinks — high credit inflow from many unique sources
  with low debit outflow ratios.

Pattern 7 — Structuring / Smurfing Detection
  Detects accounts clustering multiple deposits/withdrawals below reporting thresholds
  on the same day that collectively sum to a high value.

Pattern 8 — Money Flow Graph Construction
  Generates the transaction-weighted NetworkX multigraph that provides structural data
  for cycle, pathway, and hub algorithms.

Pattern 9 — Circular Flow (Multi-Hop Cycle) Detection
  Locates directed loops of length 3 to 6 across multiple entities in the graph
  with consistent transfer values.

Pattern 10 — Money Trail Tracing
  Applies FIFO tracking from a requested starting credit to trace the path of funds
  across subsequent debit entries.

Pattern 11 — High-Throughput Pass-Through Accounts [NEW]
  Identifies high-volume accounts that route incoming credits to outbound debits in a
  rapid sequence, retaining a negligible percentage of the flow.

Pattern 12 — Matched Internal Flow Hub [NEW]
  Finds matching debit/credit pairs between different internal/observed accounts
  linked by date, amount, references, or counterparties.

Pattern 13 — Cross-Statement Money Flow Links [NEW]
  Links money transfers across separate physical document statements (doc_ids)
  to trace fund flows that cross organizational bounds.

Pattern 14 — Large Credit Followed by ATM/Cash Withdrawal Chains [NEW]
  Identifies accounts receiving large credits that are immediately cashed out
  via ATM withdrawals or cash debits within a tight window.

Pattern 15 — Accumulation / Holding Accounts [NEW]
  Flags accounts whose balances grow steadily over time, retaining a high percentage
  of incoming transfers without distributing them.

Pattern 16 — Repeated Round-Value Debit Pattern [NEW]
  Detects systematic structuring or layering involving repeated transfers of round values
  (e.g., multiples of ₹1,000, ₹10,000, or ₹50,000).

Pattern 17 — Shared UPI Identifier Across Multiple Accounts [NEW]
  Flags coordinated account networks by detecting the same UPI Virtual Private Address (VPA)
  in transaction narrations across different accounts.

Pattern 18 — Reversal Clusters [NEW]
  Identifies accounts with repeated debit/reversal events, indicating testing or
  manipulation of transaction networks.

Pattern 19 — Low-Value Reciprocal Account Testing [NEW]
  Detects very small transfers (₹1, ₹2) exchanged bidirectionally between accounts to
  test account status prior to executing large transfers.

Pattern 20 — High-Risk Internal Flow Hub Ranking [NEW]
  Identifies critical routing nodes by computing graph degree centrality, betweenness,
  and transaction flow volume.

Pattern 21 — Top Suspicious Account Ranking [NEW]
  Aggregates all detections to identify the highest-risk accounts based on the
  variety of distinct suspicious patterns triggered.

     Detectors retrieve operational cutoffs from the baseline, allowing the engine
     to adjust parameters automatically for different case sizes.
  2. Non-Disruptive Extensibility: Added 11 new patterns without modifying the core

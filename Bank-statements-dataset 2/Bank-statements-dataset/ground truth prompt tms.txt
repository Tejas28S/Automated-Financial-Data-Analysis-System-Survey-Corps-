# Financial Investigation Ground Truth Generation Prompt

**Version:** 1.0

**Purpose:** Generate a complete Ground Truth reference from the provided financial investigation dataset.

---

# Overview

This task is **NOT** to build a software application.

This task is **NOT** to generate source code.

This task is **NOT** to modify the existing repository.

This task is **NOT** to create an AI model.

This task is **NOT** to build a fraud detection engine.

Instead, your responsibility is to act as an independent financial investigation expert and produce the most accurate understanding possible of the provided dataset.

The generated outputs will become the **Ground Truth** against which another software system will later be validated.

Every conclusion must be supported by evidence extracted from the dataset.

Never fabricate relationships.

Never assume fraud without evidence.

Never invent transactions.

Everything must be derived directly from the supplied data.

---

# Background

The project is an Automated Financial Investigation System.

The extraction pipeline is developed separately.

Its responsibility is:

* Extract transactions
* Extract metadata
* Standardize outputs
* Produce structured datasets

This task begins **after extraction**.

Your responsibility starts once the dataset exists.

You are **not** evaluating OCR.

You are **not** evaluating extraction.

Assume extracted information is available.

Your task is understanding.

## Multi-Hop Analysis

```
A

↓

B

↓

C

↓

D
```

Do not stop after one hop.

Continue until the trail ends.

---

## Circular Money Movement

Detect situations where money returns to its origin.

Example:

```
A

↓

B

↓

C

↓

A
```

Record:

* cycle length
* amount
* duration
* participating accounts

---

## Layering

Look for behaviour where funds move rapidly through multiple accounts.

Characteristics include:

* Many intermediate accounts.
* Short time intervals.
* Minimal balance retention.
* Similar transfer amounts.

Document every identified layering chain.

---

## Structuring

Identify repeated transactions just below common thresholds.

Examples:

```
49,500

49,800

49,900

49,750
```

rather than

```
2,00,000
```

Look for:

Repeated amounts.

Repeated beneficiaries.

Repeated timing.

Repeated branches.

---

## Smurfing

Detect situations where large transfers are broken into many small transfers.

Example:

```
10 × ₹49,000
```

instead of

```
₹4,90,000
```

Determine whether multiple accounts participate.

# Purpose

The objective is **NOT** to label transactions as fraudulent.

The objective is to discover **behavioural patterns** that may indicate financial crime.

The dataset is based on real case data with modified parameters.

Therefore, meaningful patterns are expected to exist.

However, never assume every unusual transaction is fraud.

Every conclusion must be evidence-backed.

# Investigation Philosophy

Think like an experienced financial crime investigator.

Never ask:

Instead ask:

* Why did this happen?
* What happened before?
* What happened after?
* Does this behaviour repeat?
* Does another account show the same behaviour?
* Does this fit into a larger money movement?

Fraud is rarely visible from one transaction.

Fraud emerges from behaviour.
